# ZMeta Name And Mark Usage

Status: current-main advisory governance.

This document gives project-level naming guidance. It is not a trademark
registration, legal opinion, or formal brand license. Consult counsel before
filing or enforcing any trademark.

## Purpose

The ZMeta name should identify the upstream open specification and reference
stack without preventing accurate descriptive use by implementers.

Apache License 2.0 does not grant trademark rights except for reasonable and
customary descriptive use. This guidance explains how the project expects the
name to be used around conformance and compatibility claims.

## Acceptable Descriptive Use

Acceptable examples:

- "implements ZMeta v1.1.8";
- "ZMeta-compatible adapter";
- "validated against the ZMeta v1.1.8 conformance corpus";
- "uses the ZMeta schema and policy pack";
- "private ZMeta-derived dialect, not upstream-compatible."

Those statements should be accurate, scoped, and backed by validation evidence
when they imply compatibility or conformance.

## Uses That Need Care

Do not use the ZMeta name in a way that suggests:

- upstream endorsement where none exists;
- standards-body certification where none exists;
- conformance without validation evidence;
- compatibility after changing governed semantics;
- ownership of the open ZMeta architecture by a private vendor or product.

Private products, forks, or dialects should use names that distinguish them
from upstream ZMeta.

## Conformance Labels

Use `CONFORMANCE.md` for claim language. A conformance or compatibility claim
should identify the release tag, manifest hash or release hash, test evidence,
and any limitations.

## Industry Conversations

When sharing ZMeta in industry circles, cite the public repository, tagged
release, release notes, defensive publication, and conformance docs. Avoid
describing unpublished private extensions as "ZMeta" until they are governed,
versioned, documented, and publicly released.
