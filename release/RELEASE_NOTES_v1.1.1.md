# ZMeta v1.1.1 Release Notes

**Status:** Patch release
**Compatibility:** No schema-contract change; v1.0 remains locked and the
existing v1.1.0 extension vocabulary is unchanged.

## Summary

ZMeta v1.1.1 hardens the reference implementation and deployment packaging
around the v1.0 contract and v1.1.0 extension branch.

This release addresses integration feedback from adapter and gateway validation:
ingress adapters now normalize UTC offset timestamps to the strict trailing `Z`
wire form, operational adapter outputs include explicit fallback timing quality
when the source stream does not provide better timing metadata, protobuf decoding
has bounded input handling, CoT emission skips are visible in gateway metrics,
and release artifacts can be checksummed and signed with detached PGP
signatures.

The semantic contract hash is unchanged from v1.1.0 because the normative
schema, policy pack, and semantics contract are unchanged.

## Changes

- Normalized ingress adapter timestamps to UTC `Z` output across CoT, JREAP,
  KLV, MAVLink, KrakenSDR, Moth, SignalHunter, and EO-CV paths.
- Added explicit fallback `payload.timing_quality` for adapter-produced
  OBSERVATION, INFERENCE, and STATE events when source timing metadata is not
  available.
- Hardened protobuf decoding with message-size, field-size, payload-size,
  JSON-depth, nested-message-depth, invalid-field-number, and unsupported-wire
  checks.
- Added gateway CoT skip counters and reason metrics for unprojectable
  STATE_EVENTs.
- Added optional deployment policy variants for strict producer authority and
  Profile L timing-degrade behavior outside the hashed reference `policy/`
  directory.
- Added detached PGP release checksum/signature helper tooling and release
  checklist guidance.
- Tightened pytest collection and temp-directory handling for generated
  release/cache artifacts.

## Notes

The release keeps the current schema file names and event vocabulary:

- Locked contract: `zmeta_version: "1.0"`
- Experimental extension branch: `zmeta_version: "1.1.0"`
- Repository release tag: `v1.1.1`

Detached signatures require a local GnuPG installation and signing key. The
checksum manifest is generated by `release/sign_release_artifacts.py` and should
be uploaded with the release zips.
